## 2026-11-12 · 디자인 탐색과 목표 기능

**목표**: 로그인 없이 화면을 보며 디자인을 정하고, 목표 설정 기능을 넣는다.

**한 일**
- **데모 모드**를 만들었어요 (`DEMO_MODE=1`, 개발 서버 전용).
  - Supabase 쿼리 빌더 흉내를 내는 메모리 DB로, 샘플 멤버 6명과 글 28개가 들어 있어요.
  - 글쓰기, 댓글, 반응, 채택, 목표까지 실제처럼 동작해요.
- **색 테마 6종**을 만들었어요: 세이지, 노트, 종이, 미드나잇, 클린 블루, 말랑.
  - 하드코딩된 색과 모서리 값을 모두 CSS 변수(토큰)로 바꿔서, `html[data-theme]` 하나로 전체가 바뀌어요.
  - 코드 하이라이팅 색도 테마별 토큰으로 바꿔서 다크 테마에서도 잘 보이게 했어요.
- **레이아웃 5종**을 만들었어요: 플로팅, 노트형 사이드바, 타임라인, 대시보드, 갤러리.
  - 메뉴 4가지(떠 있는 메뉴, 상단 바, 사이드바, 아이콘 레일), 글 목록 모양 4가지(카드, 행, 타임라인, 타일), 홈 구성 5가지를 조합해요.
  - 타임라인 틀에는 피드에서 바로 쓰는 **빠른 입력창**을 넣었어요. 첫 줄이 제목이 돼요.
- 개발 서버 전용 **디자인 미리보기 패널**로 색과 틀을 바로 바꿔 볼 수 있게 했어요.
- 직접 비교한 뒤 **대시보드 틀 + 세이지 색**을 기본값으로 정했어요. 테마는 설정 화면에서 사용자가 고를 수 있어요.
- **목표 기능**을 넣었어요.
  - 주간 기록 목표: 주 N회, 진행 막대 표시, ± 버튼으로 조절
  - 이번 주 할 일 체크리스트
  - 지난주에 못 끝낸 목표 가져오기
  - 내 프로필에서는 편집 가능하고, 다른 멤버의 목표는 읽기 전용으로 보여요.
- 이모지 아이콘(👍💡🔥🎯)을 선 아이콘(Phosphor)으로 바꿨어요. ui-ux-pro-max 점검 기준을 따른 거예요.
- **포트폴리오 문서 체계**를 만들었어요.
  - `docs/portfolio.md`(소개), `devlog.md`(일지), `decisions.md`(결정 기록), `roadmap.md`(로드맵)
  - 다음 세션도 자동으로 기록하도록 `CLAUDE.md`에 규칙을 넣었어요.

**결정과 이유**
- 디자인을 말로 고르지 않고 **실제 화면에 입혀서 비교**했어요. 미리보기 그림보다 실제 데이터가 들어간 화면이 판단에 훨씬 정확했어요.
- 색(테마)과 틀(레이아웃)을 **따로 바꿀 수 있게 분리**했어요. 조합을 독립적으로 비교할 수 있어서예요.
- 레이아웃은 **쿠키**에, 테마는 **localStorage**에 저장해요.
  - 레이아웃은 서버가 다른 HTML을 그려야 해서 쿠키가 필요해요.
  - 테마는 CSS 변수만 바꾸면 돼서 브라우저 저장소로 충분해요.
  - 둘 다 `<head>` 인라인 스크립트로 첫 화면에서 깜빡임 없이 적용돼요.
- 목표를 **멤버끼리 볼 수 있게** 했어요. 소규모 스터디에서는 서로의 목표가 보이는 것만으로 꾸준함에 동기가 돼요.

**문제와 해결**
- 테마를 바꿨는데 글자색이 늦게 바뀌는 문제 → `body`에 걸어 둔 색 전환 애니메이션 때문이었어요. 전환을 지웠어요.
- 테마 CSS를 고쳤는데 반영되지 않는 문제 → 개발 서버 캐시가 원인이었어요. `.next`를 지우고 다시 실행했어요.
- 데모 모드에서 `new Date()` 프리렌더 오류 → 실제 모드와 달리 쿠키를 읽지 않아서 Next.js가 정적 페이지로 판단했어요. `connection()`으로 요청 시점 렌더링을 명시했어요.
- React 린트 규칙: 렌더링 중 `Date.now()` 호출, effect 안의 `setState`, 전역값 직접 수정 → `useSyncExternalStore`와 모듈 함수로 정리했어요.
- 데모 DB에 `goals`를 추가했는데 목표가 비어 보이는 문제 → 개발 서버의 HMR이 `globalThis`에 이전 데모 DB를 그대로 들고 있었어요. 서버를 재시작해서 해결했어요.
- 포트폴리오 스크린샷 자동 캡처
  - 헤드리스 Edge `--screenshot`은 처음 한 번만 성공하고, 이후 시도는 파일 없이 종료됐어요.
  - `agent-browser`는 응답 없이 멈췄어요.
  - 대시보드 한 장만 확보했고, 나머지는 보류했어요.
  - 뒤에 알고 보니 한 번은 성공했는데, bash에서 `"$D\\$n.png"`의 `\$`가 변수 대신 글자로 처리돼 `screenshots$n.png`라는 엉뚱한 이름으로 저장된 거였어요. 경로를 고쳐도 이후 캡처는 여전히 불안정했어요.
- **git 저장소 시작**: `C:\Code study`를 루트로 `main` 브랜치를 만들고 첫 커밋을 남겼어요.
  - 커밋 이메일은 GitHub의 noreply 주소를 써서, 공개 저장소에서도 개인 이메일이 노출되지 않게 했어요.
  - `.gitattributes`로 줄바꿈을 LF로 통일하고, `.env.example`만 커밋되게 했어요. 실제 키가 들어가는 `.env.local`은 제외돼요.
- **GitHub 공개 저장소**로 올렸어요: https://github.com/chaniipyc/study-log
  - 올리기 전에 추적 파일 전체에서 개인정보와 비밀 값이 없는지 검색했어요.
  - 저장소 첫 화면용 소개 README를 추가했어요.

## 2026-11-11 · 기획과 MVP

**목표**: 스터디에 필요한 기능을 정리하고, 로그인부터 기록·질문까지 되는 첫 버전을 만든다.

**한 일**
- `find-skills`로 스킬 생태계를 검색했어요. 이미 설치된 스킬과 비교해 쓸 스킬을 골랐어요 (`docs/portfolio.md`의 "AI 도구 활용" 참고).
- 기능, 템플릿, 단계별 로드맵을 기획했어요. 원칙은 **편의가 최우선**이었어요.
- Next.js 16 + Tailwind 4 + Supabase로 MVP를 구현했어요.
  - GitHub·Google 소셜 로그인
  - 피드: 언어 필터, 카드 목록
  - 글쓰기: 마크다운, 템플릿 5종, 자동 임시저장, `Ctrl+Enter`, Tab 들여쓰기, 미리보기
  - 블로그 링크 공유
  - Q&A: 답변 대기·해결 필터, 답변 채택
  - 반응 3종, 댓글
  - 멤버 목록과 프로필: 12주 잔디 히트맵, 연속 기록일
- DB 스키마와 RLS(행 단위 보안)를 작성했어요 (`supabase/schema.sql`).

**결정과 이유**
- **외부 블로그 링크도 기록으로 인정**했어요. 이미 velog나 티스토리에 쓰는 사람에게 같은 내용을 두 번 쓰게 하면 꾸준함이 깨져요.
- **비밀번호 없는 소셜 로그인만** 쓰기로 했어요. 10명 이하 스터디라 가입 장벽을 최소화하는 게 중요했어요.
- **템플릿**을 넣었어요. 기초가 부족한 멤버도 빈칸만 채우면 정리가 되도록 TIL, 개념 정리, 문제풀이, 주간 회고, 질문 템플릿을 준비했어요.

**문제와 해결**
- Next.js 16에서 `middleware.ts`가 **`proxy.ts`로 이름이 바뀐** 걸 공식 문서에서 확인하고 반영했어요.
- Supabase가 **2026-10-30부터 새 테이블을 Data API에 자동으로 공개하지 않게** 바뀌었어요 → 스키마에 `GRANT`를 명시했어요.
- 질문 작성자가 **남의 댓글을 '채택'으로 바꿔야 하는데** RLS상 본인 댓글만 수정할 수 있는 문제가 있었어요.
  - 작성자 확인을 함수 안에서 하는 `accept_answer` RPC를 만들었어요.
  - 댓글 수정 권한을 `update (body)` 컬럼으로 제한해서 채택 여부를 직접 조작할 수 없게 했어요.
- Next.js 16의 Cache Components 때문에 "Suspense 밖에서 요청 데이터 접근" 오류가 났어요 → 페이지마다 Suspense와 스켈레톤을 둬서 해결했고, 덕분에 화면이 스트리밍으로 부드럽게 뜨게 됐어요.
